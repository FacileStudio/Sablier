# Sablier — API

Every HTTP route, generated by reading `apps/api/main.go` and each module's `router.go`.

## Conventions

- All application routes live under `/api`. There is a single
  `router.Route("/api", ...)` block in `main.go` and every module registers inside it.
- Authenticated routes expect `Authorization: Bearer <token>`, where the token is either
  a browser session token (30-day expiry) or a user's API token (no expiry). Both are
  accepted everywhere.
- Request and response bodies are JSON.
- Errors come back as JSON from `tronc/httpjson`. `tronc/errors` maps `Invalid` to 400,
  `Unauthorized` to 401, `Conflict` to 409, and `Internal` to 500.

## Service routes

| Method | Path | Auth | Response |
|---|---|---|---|
| GET | `/health` | no | `{"status":"ok"}` — liveness, touches no dependency |
| GET | `/ready` | no | `{"status":"ready"}`, or 503 `{"status":"not_ready"}` if the Postgres ping fails |
| GET | `/api/health` | no | Same handler as `/health` |
| GET | `/api/ready` | no | Same handler as `/ready` |
| GET | `/docs` | no | Scalar API reference, served by `tronc/apiref` |
| GET | `/docs/openapi.json` | no | OpenAPI 3.1 document built from each module's `documentation.go` |
| GET | `/files/*` | no | Static file server rooted at `STORAGE_DIR`; it still serves avatars uploaded before Registre owned pictures |
| GET | `/*` | no | SPA catch-all, mounted only when `CLIENT_DIR` contains an `index.html` |

`tronc/health.Mount` deliberately registers the probes at both the root and under `/api`,
so the same probe answers whether or not the edge proxy forwards only `/api/*`.

The reference is generated from the hand-written registry in each module's
`documentation.go`, whose paths are relative to the `/api` server entry. `TestEveryRouteIsDocumented`
in `apps/api/apiref_test.go` walks the live router and fails when a route is missing from it,
so the registry cannot quietly drift out of date.

## Auth

| Method | Path | Auth | Body | Response |
|---|---|---|---|---|
| GET | `/api/auth/config` | no | — | `{"sso_only": bool, "oidc_enabled": bool}` |
| GET | `/api/auth/oidc` | no | — | 302 to the provider, setting an `oidc_state` cookie |
| GET | `/api/auth/oidc/callback` | no | — | 302 to `OIDC_SUCCESS_URL` with the session token |
| POST | `/api/auth/sync-profile` | yes | — | Re-pulls name and avatar from the provider |

Sign-in goes through Registre only. There is no register or login route, and no password
anywhere: the OIDC routes exist only when `OIDC_ISSUER` is configured (required when
`APP_ENV=production`) and the provider's discovery document loaded successfully. The
desktop app, the CLI and scripts keep using a named API token (see below).

## Users

All routes require authentication.

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/users` | — | `{"users":[User]}` |
| GET | `/api/users/me` | — | `{"user":User}` |
| GET | `/api/users/{id}` | — | `{"user":User}` |
| PATCH | `/api/users/me` | any of `name`, `email`, `color`, `rate`, `rate_type`, `workday_hours` | `{"user":User}` |
| GET | `/api/users/me/api-token` | — | `{"has_token", "name"?, "created_at"?}` |
| POST | `/api/users/me/api-token` | `{"name"}` | 201 `{"token","name","created_at"}` — the only time the token is returned |
| DELETE | `/api/users/me/api-token` | — | `{"deleted":true}` |

The password is Registre's. `User` carries `locale` (`fr`, `en`, `es` or `de`), set from the
Registre profile at each sign-in.

`User` is `{id, email, name, avatar_url, avatar_source, color, rate, rate_type,
workday_hours, created_at}`. `avatar_source` is `oidc` when `avatar_url` is the
Registre picture URL, which answers 404 for a user with no picture, so clients fall back
to initials. Pictures are set at `https://sso.facile.studio/account`; Sablier has no
upload endpoint.

## Spaces

Registre owns shared spaces. Create, rename, invite, role changes, removal and leaving happen
at `https://sso.facile.studio/spaces`; Sablier mirrors the result and offers no write route.
All routes below require authentication. Space ids are UUIDs.

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/spaces` | — | `{"spaces":[Space]}` — only spaces the caller belongs to |
| GET | `/api/spaces/{spaceId}` | — | `Space` |
| GET | `/api/spaces/{spaceId}/members` | — | `{"members":[Member]}` |

`Space` carries the caller's own `role` alongside `id`, `name`, `description`,
`registre_space_id` (empty until linked), `created_at`, and `updated_at`. `Member` is
`{id, space_id, user_id, user_email, user_name, user_color, user_avatar_url, role, joined_at}`.
Roles are `owner`, `admin`, and `member`.

### Registre sync

`POST /api/registre/sync` is Registre's nudge. It takes no body and no credentials and answers
`202`; it only makes the next pull happen within seconds. Mounted only when `OIDC_ISSUER` is set.

At boot Sablier imports its unlinked spaces into Registre once (`POST <issuer>/api/directory/import`,
members by subject under the issuer, else email), retrying from 10 s up to every 5 min until
Registre answers. Only then does it pull `GET <issuer>/api/directory/snapshot` at boot, every
5 minutes and after each nudge, with the OIDC client id and secret as HTTP Basic. Applying a
snapshot:

- links a Registre space to the row with its `registre_space_id`, else to the oldest unlinked
  space with the same name (case-insensitive), else creates it; the name is Registre's;
- resolves each member by porte identity, then by email (adding the identity), else
  pre-provisions a user with Registre's name and picture plus the identity, so the first
  sign-in lands on it;
- sets roles (`owner`, `admin`, anything else `member`) and removes members of linked spaces
  who hold a Registre identity but are absent from the snapshot. Local password accounts, agent users,
  unlinked spaces and linked spaces missing from the snapshot are left alone.

## Projects and tasks

All routes require authentication. Tasks are nested under their project.

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/projects` | — | `{"projects":[Project]}`; accepts `?space_id=` (see below) |
| POST | `/api/projects` | `{"name","description","icon","space_id"}` | 201 `Project` |
| GET | `/api/projects/{id}` | — | `Project` |
| PUT | `/api/projects/{id}` | `{"name","description","icon"}` | `Project` |
| DELETE | `/api/projects/{id}` | — | `{"deleted":true}` |
| GET | `/api/projects/{id}/tasks` | — | `{"tasks":[Task]}` |
| POST | `/api/projects/{id}/tasks` | `{"name"}` | 201 `Task` |
| PUT | `/api/projects/{id}/tasks/{taskId}` | `{"name","status"}` | `Task` |
| DELETE | `/api/projects/{id}/tasks/{taskId}` | — | `{"deleted":true,"sessions_unlinked":n}` |

`?space_id=` on the project and time-entry lists: absent keeps your personal rows (no space),
`all` keeps your personal rows plus every space you belong to, and a space id keeps that space.
Personal rows are private: a project is yours when you own it, an entry when you or one of
your agents booked it. Every `/api/projects/{id}` route answers 404 for a project you cannot see.
A space you are not a member of returns 404, and so does creating a project in one.

`GET /api/tasks/search?q=&limit=` searches the tasks you can see (`limit` 1 to 50, default
20) and returns `{"results":[{task:{id,name,facile_id}, project:{id,name,icon},
space:{id,name}|null, last_used_at|null, opus}]}`. Your recent tasks come first, by your
latest entry, then open Opus tasks, then task-name matches, then project-name matches.

`Project` is `{id, name, description, icon, owner_id, space_id, created_at, updated_at}`. `Task` is
`{id, project_id, name, status, actor_id, created_at, updated_at}`, with `status` one of
`to-do`, `in-progress`, `in-review`, `done`. A non-numeric `{id}` returns 400
`invalid project id`.

## Time entries

All routes require authentication. The timer routes act on the calling user's own timer.

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/time-entries` | — | `{"entries":[TimeEntry]}` |
| GET | `/api/time-entries/running` | — | `{"entry": TimeEntry \| null}` for the caller |
| POST | `/api/time-entries/start` | `{"project_id","task_id","space_id"}` | 201 `TimeEntry` |
| POST | `/api/time-entries/stop` | — | `TimeEntry` |
| POST | `/api/time-entries/pause` | — | `TimeEntry` |
| POST | `/api/time-entries/resume` | — | `TimeEntry` |
| POST | `/api/time-entries` | `{"project_id","task_id","space_id","started_at","stopped_at"}` | 201 `TimeEntry` |
| PUT | `/api/time-entries/{id}` | `{"project_id","task_id","started_at","stopped_at"}` | `TimeEntry` |
| DELETE | `/api/time-entries/{id}` | — | `{"deleted":true}` |

`GET /api/time-entries` takes four query parameters: `space_id`, `project_id`, `user_id`,
and `running=true`. `running=true` lists the running entries in scope, still narrowed by
`project_id` and `user_id` when given. Non-numeric `project_id` or `user_id` return 400.
`/api/time-entries/running` is the caller's own timer and takes no `space_id`.

Start and create ignore a `space_id` in the body: the entry takes its project's space,
and a project you cannot see is refused with 400.

`TimeEntry` is `{id, project_id, project_name, task_id, task_name, space_id, user_id,
user_email, user_name, user_color, user_avatar_url, user_kind, started_at, stopped_at,
paused_at, paused_duration_ms, created_at, updated_at, attribution_source,
attribution_confidence, needs_review}`. `attribution_source` is one of `explicit`, `opus`,
`name`, `running`, `ai`, `fallback` or `manual`, and null on an entry a person booked.
`project_name` is filled on list and review rows. A running entry has `stopped_at: null`; a paused one also has a
non-null `paused_at`, with accumulated pause time in `paused_duration_ms`.

Starting a timer fires a `timer_started` webhook and a `time_entry.created` pool event;
stopping fires `timer_stopped` and `time_entry.updated`.

## Review

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/review` | — | `{"entries":[TimeEntry], "drafts":[Draft]}` |
| POST | `/api/review/{entry_id}` | `{"task_id"}`, `{}` or empty | `TimeEntry` |

`entries` are the entries flagged `needs_review` that belong to you or to your agents.
`drafts` are your drafts over the last 48 hours, each with its `suggestion`. Posting a
`task_id` moves the entry to that task, its project and its space; an empty body accepts
it as it is. Both clear the flag and set `attribution_source` to `manual`, so a replayed
agent session never moves the entry again.

## Antenne

Event-bus connection settings and per-event toggles. All routes require authentication.

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/api/antenne` | — | `{"pool_settings":{...}, "connected", "connect_error"?, "from_env"?}` |
| PUT | `/api/antenne` | `{"antenne_url","antenne_secret","antenne_enabled"}` | Same shape; reconnects or disconnects immediately |
| POST | `/api/antenne/sync` | — | `{"projects_synced","tasks_synced"}` |
| GET | `/api/antenne/events` | — | `{"events":[{"event","enabled"}]}` |
| PUT | `/api/antenne/events` | `{"events":[{"event","enabled"}]}` | `{"events":[...]}` |

The toggleable events are `time_entry.created`, `time_entry.updated`,
`agent_session.created`, `agent_session.updated`, `project.created`, `project.updated`,
`project.deleted`, `task.created`, `task.updated`, and `task.deleted`. `from_env` is true
when the returned URL and secret came from `ANTENNE_URL` / `ANTENNE_SECRET` because
no settings row exists yet.

## Notifications

Web Push subscriptions. `vapid-public-key` is deliberately unauthenticated so the service
worker can register before the user has a session.

| Method | Path | Auth | Body | Response |
|---|---|---|---|---|
| GET | `/api/notifications/vapid-public-key` | no | — | `{"public_key"}` |
| POST | `/api/notifications/subscriptions` | yes | `{"endpoint","p256dh","auth"}` | `{"saved":true}` |
| DELETE | `/api/notifications/subscriptions` | yes | — | `{"deleted":true}` |
| POST | `/api/notifications/test-broadcast` | no | `{"title","body","icon"}` | `{"sent","failed"}` |

`test-broadcast` pushes to every subscription and carries a `TEST ONLY — remove before
production` comment in `modules/notifications/router.go`. It takes no authentication.
Treat it as a development affordance, not a supported endpoint.
